# Agent Diagnostics

Complete local recording is the default for ordinary chats and Agent runs, including existing installations after the automatic-capture migration. Settings allow a subsequent explicit reduction or opt-out. The diagnostics screen explains this behavior. Recording reuses AgentDiagnosticsRecorder and NativeToolTraceLogger's existing Documents/Diagnostics directory; no separate logging service or cloud upload is used.

Files are written atomically to the existing `Documents/Diagnostics` directory as paired JSON and readable text snapshots. They are visible through Files because the existing app target enables document sharing. Full logs never use Application Support, CloudKit, analytics, or automatic export.

Each stable session basename also owns `-stage-events.jsonl`, `-manifest.json`, and `.raw.enc`. Transport callbacks enqueue work on a bounded utility queue without disk or encryption work on the stream/UI. The adapter records its actual delivered byte boundaries (not TLS packet boundaries), attempt UUID, request and round correlation, offsets and hashes. Complete UTF-8 lines are decoded after buffering, with invalid UTF-8/replacement-character/partial-EOF flags; unknown lines are retained. The same observer instruments direct chat and the SDK fetch adapter. SDK, StreamData, provider-event, accumulator and projection stages preserve their own source hashes. These diagnostic reconstructions are not proof that a particular provider generated the Build98201 corruption; comparison with captured source is still required.

Exact request URL/headers/body and response chunks are automatically retained as independently authenticated AES-256-GCM records in `.raw.enc`. `aad` binds run, attempt, sequence and record kind; each record has a fresh nonce. The random 256-bit key lives in a device-only AfterFirstUnlock Keychain item. Key failure never falls back to plaintext: the manifest reports loss and error. Files use Data Protection, and the directory is excluded from backups. The sidecar is JSONL envelopes containing base64 CryptoKit combined sealed boxes; deliberate decryption/sharing is a separate operation. Existing JSON/TXT schema-v2 readers remain compatible.

The manifest checkpoints once per second and at transport/terminal boundaries. It records the raw sidecar digest, last sequence, file links, write errors and explicit dropped bytes/truncation under the 16MiB pending-work/256MiB per-session budget. JSON/TXT conversation checkpoints are coalesced to at most once per second while streaming. Cancellation retains accepted bytes and a terminal checkpoint. Retention and explicit deletion remove all companions together. A process killed between checkpoints may leave append-only evidence and an incomplete manifest; no success is inferred from a stale running snapshot.

Validation remains open until focused journal/transport tests, current Apple compilation, signed physical iPad default-install/upgrade, force-quit/relaunch and stream-latency checks actually pass. This document describes implementation, not physical acceptance.

Readable per-delta event records refer to `-stage-snapshots.json`; exact per-event content remains encrypted. Complete content/reasoning snapshots are coalesced before credential redaction, rather than publishing fragments of a key across multiple SSE records. Snapshots retain up to32MiB of stage text with explicit loss reporting at the budget. Request credentials are additionally masked if echoed in later content. The existing JSON/TXT snapshot redactor receives the same known credentials. These companions are included in retention/deletion as one session.

`py -3 Scripts/Diagnostics/compare_chat_stages.py <session-manifest.json>` compares eligible OpenAI-shaped source/SDK/StreamData snapshots without executing code, calling tools or uploading content. Output contains hashes and offsets, not the conversation. It refuses ambiguous multi-attempt round correlation, unknown provider mappings and incomplete capture. Comparisons are redacted; exact encrypted-source inspection and actual UI rendering remain separate acceptance obligations.

The central redactor is applied before persistence and again to the readable export. Hidden chain-of-thought is never reconstructed; only provider-visible reasoning content already exposed by the API may be recorded.

NativeToolTraceLogger uses that same structured redactor before stringifying values, including JSON fallback errors. Numeric token counters remain useful; credential keys and nested values are masked. Legacy trace files no longer disappear under a separate silent30-file/20MiB rotation. They are included in the diagnostics storage tally and remain user-manageable through Files.

When the diagnostics screen opens, an incomplete session that has remained `running` without an update for ten minutes is shown as `interrupted`. Its persisted JSON and readable log are preserved unchanged for investigation.


New and upgraded installations retain sessions until explicit deletion. The one-time retention migration cancels the former implicit 50-session deletion; later user-selected limits are honored. Selecting a finite limit in Settings requires a destructive-action confirmation explaining that older sessions and encrypted companions will be removed on the next session start. Diagnostics shows total local storage and a warning above512MiB. Capture budgets still report explicit dropped bytes; no promise of unbounded disk capacity is made.

The existing session screen prepares an optional sanitized ZIP on a utility task, then shows a review sheet before ShareLink. An allowlist includes that session's JSON/TXT, capture manifest, event journal and snapshots. Encrypted raw, Keychain material, unrelated files and symlinks are excluded. Export performs another structural redaction pass, hashes both source and exported bytes, records missing assets and any omitted partial crash tail, and fails closed on malformed complete events or its64MiB/file256MiB/export safety bounds. It never deletes the source. Temporary exports have complete Data Protection, are excluded from backups, and are removed when review is dismissed. A killed process may leave an OS-managed temporary ZIP; physical cleanup/backup-exclusion checks remain open.

CI embeds source commit and exact SPM resolved states/hash from the actual checkout, without authenticated repository URLs. These facts plus OS/locale/timezone are copied into each new session at capture time; exporting old sessions never substitutes the current build's identity. Local builds without running Scripts/CI/write_diagnostics_build_provenance.py explicitly report unavailable provenance. The export manifest keeps capture and export environments separate. Files from an active session are independent snapshots and are labeled accordingly; hash agreement is not atomic cross-file coherence or UI parity.

Raw local unlock/review, a portable credential-safe raw artifact, deterministic SDK/agent/UI replay, physical file-protection checks and a reproduced broken NVIDIA session remain separate unfinished acceptance obligations. The sanitized ZIP and stage comparison do not establish those passes.

HanlinChatCore now exposes HanlinCapturedStreamReplay for explicitly supplied captured/synthetic response chunks, their monotonic offsets and provider configuration. It feeds the original HanlinChatStreamParser and HanlinAISDKAgentEngine through a single-use in-memory fetch. No URLSession or tool executor exists in this path. It reports content/reasoning, finish/error boundaries, invalid source UTF-8, missing completion, first direct-vs-SDK byte mismatch and attempted retries; another fetch fails locally instead of replaying one response twice. Default playback is immediate; optional positive playback speed preserves captured timing and supports cancellation. The response-only harness does not recreate original request context, decode the encrypted vault, execute APIManager, or certify ChatBubble rendering. Its new five-case package verification is pending.

Provenance generation runs after Xcode package resolution and refuses a lockfile whose repository/revision identities disagree with requested exact project pins. The checked-in app lockfile was older than the current project references; generating the resource before resolution would have mislabeled its dependency graph. The source commit, workspace-modified flag and the actual post-resolution lock hash remain separate facts.
