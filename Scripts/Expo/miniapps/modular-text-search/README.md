# חיפוש טקסטים מודולרי — Hanlin MiniApp 1.4

This source project ports the user-supplied modular text-search package to Hanlin's installed Expo, NativeScript native API bridge, and ScriptWidget presentation runtime. The package keeps the original search/source adapters and produces an editable, source-preserving `.hanlinExpo` archive.

## Application and system entrypoints

| Entrypoint | Implementation |
| --- | --- |
| MiniApp application | React state with the installed native Expo SwiftUI controls |
| Shortcuts / App Intent | The manifest's search action, with a prepared native ScriptWidget snippet |
| Share | Incoming text/URL context enters the registered search action and application continuation |
| Translation | Prepared native ScriptWidget presentation with an editable text input, search and replacement/close actions |

`script.json` is the authority for IDs, action exports and `nativePresentations` source paths. The JavaScript action bundle and native presentation resources are packaged together. Native presentations use their original renderer in the host's registered system extensions.

The app keeps Hebrew/English UI, quick queries, modular engine/source adapters, advanced engine/search/sort/filter/text/debug options, grouped search results, full-text loading and versions, pagination, source links, and visible progress/errors. The application uses native List, Section, TextField, Button, navigation and settings controls.

The `src/engines` and `src/logic` modules preserve the supplied package's source/search logic. The `native/` subtree is self-contained for native system presentations and is retained verbatim in the installable archive and editable source copy.

## Transport and host identity

The Expo application uses the installed NativeScript JSI bridge to call Apple's URLSession for Sefaria search and full-text requests. Native completion handlers return to the React JavaScript thread through the installed bridge. The ScriptWidget presentation uses the original installed HTTP service.

Build against the SDK generated by the host version that will load the archive. The builder records its real original package versions, TypeScript compiler version and SDK manifest hash, and binds prepared `hanlinExpo` metadata to that host.

The version dimensions are distinct: `@hanlin/expo-ui` is npm package version 1.0.0, while its native bridge contract is 3.0.0. Expo's npm SDK version, `@expo/ui` native runtime version and the NativeScript native-API contract/ABI also have separate authorities. The builder reads these from the installed SDK; it does not copy stale source-package metadata over the compiled result.

This package requires the host implementation containing the current entrypoint/native-presentation and Expo UI bridge changes. An old TestFlight installation is not proof that these host changes are present. Native framework updates ship in the host app and extensions; a JavaScript archive records the matching host contract.

## Build the original source project

The project includes `hanlin.authoring.json`, a portable application `tsconfig.json`, and a separate `native/tsconfig.json`. The application uses original Expo/React declarations; the native TSX presentation uses the original ScriptWidget component/service declarations. Both are checked before packaging. The copied original JavaScript adapters remain unchanged with `checkJs: false`, while the consuming TypeScript/TSX is strict. The authoring descriptor names the application source entrypoint and explicitly includes the `native/` resource subtree. No developer-machine TypeScript paths are required.

Prepare the repository's original Expo tooling, then use the shared production builder:

```bash
npm ci --prefix Scripts/Expo
node Scripts/Expo/prepare-types.mjs
node Scripts/MiniApps/stage-sdk.mjs --output=build/MiniAppSDK --engines=expo,scriptwidget
node Scripts/MiniApps/miniapp.mjs build \
  --sdk build/MiniAppSDK --engine expo \
  --project Scripts/Expo/miniapps/modular-text-search \
  --archive build/miniapp-packages/ModularTextSearch.hanlinExpo \
  --report build/miniapp-packages/ModularTextSearch.build.json
```

From PowerShell in this directory, `./build.ps1` prepares the matching SDK, invokes the same builder and writes `dist/ModularTextSearch.hanlinExpo`. The focused GitHub Actions workflow **Package native Hanlin Expo search MiniApp** uses the shared builder and retains both the archive and its diagnostic/build report.

The archive includes:

- Actual original Metro `bundle.js` and source map.
- Script/package metadata and declared native presentation files/assets.
- `source/` with editable TypeScript, JavaScript, configuration and resources.
- `hanlin.authoring.json` with source/output digests and SDK identity.
- `hanlin.validation.json` with actual compiler findings.

Existing output archives are preserved by the CLI; use a new output path or remove a previous generated artifact deliberately before rerunning the same explicit destination.

## Agent creation, repair and direct import

The Hanlin agent uses `get_miniapp_sdk`, `write_miniapp`, `validate_miniapp`, `build_miniapp` and `import_miniapp`. The SDK exposes original documentation, declarations, native API inventory and the exact host build identity.

An invalid source-bearing import is rechecked with the real TypeScript compiler and reports file, line, column, code and message. The native diagnostics sheet can hand the original archive/source and findings to the agent for repair. Editing an extracted archive targets its retained `source/` project, and a repaired project is rebuilt before import.

Cross-app import reports a transfer as queued until the receiving MiniApps application records an actual installed or failed result. Querying the transfer ID returns that receiver result.
