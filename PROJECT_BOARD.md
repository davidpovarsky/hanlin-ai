- **Darwin `/private/var` `URL.standardizedFileURL` Asymmetry for Non-Existent Child Paths:** On Darwin (macOS/iOS/iPadOS), `URL.standardizedFileURL` (`NSString.standardizingPath`) strips the leading `/private` prefix from `/private/var/...` and `/private/tmp/...` **if and only if the target path currently exists on disk**. On physical iOS/iPadOS devices, `FileManager.default.containerURL(forSecurityApplicationGroupIdentifier:)` returns `/private/var/mobile/Containers/Shared/AppGroup/<UUID>`. If `root` (`<container>/ScriptingExtensions`) already exists on disk (`createDirectory`), `root.standardizedFileURL.path` resolves to `"/var/mobile/.../ScriptingExtensions"`, whereas a not-yet-created child (`commit.json`, `pending.json`, or a new artifact) keeps `"/private/var/mobile/.../ScriptingExtensions/..."`. Comparing `target.standardizedFileURL.path.hasPrefix(root.standardizedFileURL.path + "/")` therefore fails 100% of the time for non-existent child files on physical devices! Always canonicalize the trusted parent container URL once (`resolvingSymlinksInPath()` on the parent directory while keeping the managed root leaf unresolved) and walk relative path components with `Darwin.lstat` (`S_IFLNK` / `S_IFDIR`) rather than relying on `standardizedFileURL` prefix string matching.
