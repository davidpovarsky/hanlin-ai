## Packaged encryption

- The packaged NativeScript `SubtleCrypto.mjs` calls `NSCCrypto` for digests, HMAC and RSA-OAEP on iOS. The shipped `NSCWinterTC` binary loads Apple's Security framework and exposes references to `SecKeyCreateEncryptedData` and `CCHmac`. This is evidence of operating-system cryptography in that bridge.
- The IPA also contains independent implementations. `IOSSystemLite` links the pinned OpenSSL and libssh2 binary products. The packaged OpenSSL contains EVP cipher and TLS functions. The libssh2 binary contains SSH session negotiation and Ed25519. The packaged NodeMobile and CPython `_ssl` binaries contain OpenSSL/TLS functions. These are standard cryptographic implementations outside the operating system. The inspected paths did not show a proprietary algorithm.

Apple distinguishes operating-system encryption from industry-standard algorithms supplied outside the OS. For the latter, its documentation calls for a French encryption declaration if the app is distributed on the French App Store. App Store Connect returned HTTP 404 for the territory availability lookup, so this audit could not confirm the French distribution setting. Apple's build record reports `usesNonExemptEncryption=false` after the owner's questionnaire, with no associated app-level encryption declaration returned for this build. That records build 6601's questionnaire outcome. The classification for a standing plist entry depends on confirming that the bundled standard libraries and intended territories are covered. If Apple requires documents, obtain the approved encryption compliance code for future builds.
