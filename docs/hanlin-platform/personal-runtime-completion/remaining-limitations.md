# Hanlin Real Platform & Environmental Limitations

**Repository:** `davidpovarsky/hanlin-ai`  
**Working Branch:** `codex/agent-skills-embedded-results`  
**Document Purpose:** Record verified technical limitations imposed by Apple iOS/macOS platform architecture, compiler toolchain differences, hardware capabilities, or external requirements. Every item is backed by technical evidence and exact test runs. No artificial Hanlin policy limitation is disguised as a platform constraint.

---

## 1. Verified Platform & Runtime Limitations

| Limitation ID | Category | Nature of Limitation | Description | Technical Evidence & Root Cause | Affected Scenarios / Runtimes | Exact Next Action |
|---|---|---|---|---|---|---|
| `LIM-01` | Operating System | Apple iOS Sandbox Constraint | **Process Spawning on iOS:** iOS kernel sandbox prohibits unprivileged user applications from calling `fork()` or `posix_spawn()` to spawn arbitrary external subprocesses. | Apple iOS sandbox security model; POSIX process spawning restriction. Attempting `fork()` triggers immediate SIGKILL by kernel. | Subprocess execution in Node (`child_process.spawn`) and Python (`subprocess.Popen`). Pure JS/Python and in-process execution through NodeMobile and ios_system work normally. | In-process execution through NodeMobile Worker threads and ios_system dynamic symbol execution. Advisory warning provided when package attempts subprocess execution. |
| `LIM-02` | Operating System | Apple iOS Sandbox Constraint | **Arbitrary Native Shared Objects (`.so`, `.dylib`, `.node`):** iOS requires all executable Mach-O code to be signed and embedded in the app bundle at install time. Dynamic downloading and loading of unsigned native binaries via `dlopen()` is prohibited. | Apple kernel code-signing validation. Dynamic loading of unsigned `.dylib`/`.so` returns `EXC_BAD_ACCESS` / code signature invalid. | Native Python wheels (e.g., numpy with custom C extensions not pre-compiled), Node `.node` native addons. Pure Python (`py3-none-any`) and pure JS packages function normally. | Pure Python wheels install and run seamlessly. Packages with native extensions are flagged with an advisory warning during installation. Pre-compiled native libraries must be embedded at app bundle build time. |
| `LIM-03` | Hardware / OS | Apple Silicon / OS Requirement | **Apple Foundation Models On-Device Requirements:** Apple Intelligence (`SystemLanguageModel`) requires supported Apple Silicon hardware (A17 Pro, M-series chips or newer) and iOS 27. | Apple Developer Foundation Models documentation. Unsupported hardware or simulator without on-device model weights reports `LanguageModelError.unavailable`. | `APPLEAI-04`, `APPLEAI-05`, `E2E-P`. Managed via typed graceful fallback to other local or remote providers without crashing. | Implemented `AppleFoundationModelsProvider` with typed capability detection and graceful fallback to remote or alternative local providers. |
| `LIM-04` | External Hardware | Physical Device Requirement | **Physical Device Verification for iOS System Entitlements:** Certain Apple system capabilities (HealthKit, Camera, system calendar write prompts) require real physical device testing (`D` layer) with an authorized Apple Developer provisioning profile. | Apple sandbox requires real user interaction and physical device sensors. Simulator tests provide mock/simulated data. | Tests labeled `D` (Device layer). Executed via automated tests on simulator and marked `NOT_RUN_DEVICE` with explicit step-by-step instructions when physical device is disconnected. | Run on physical device with active provisioning profile using the built IPA artifact. |
| `LIM-05` | Host Toolchain | Windows Clang Incompatibility | **CZLib Apple Clang Header Compilation on Windows Host:** The Swift package `Packages/HanlinPlatform` depends on `ZIPFoundation`, which includes `CZLib/shim.h` containing `#import <zlib.h>`. Clang on Windows does not support Objective-C `#import` syntax for C headers outside Apple platforms. | `hanlin-platform-swift-build.log`: `ZIPFoundation/Sources/CZLib/shim.h:15:2: error: #import of type library is an unsupported Microsoft feature`. | Direct host-level `swift build --package-path Packages/HanlinPlatform` on Windows machines. SPM resolution passes (exit 0), and dependent packages (`HanlinParityMiniApp`, `HanlinSefariaMiniApp`, `HanlinTextStudioMiniApp`, `HanlinWikipediaMiniApp`) build and test cleanly. | Compile and test `HanlinPlatform` on macOS / Xcode 27 environment where Apple Clang natively handles `#import <zlib.h>`. Scenarios requiring host `swift test HanlinPlatform` are accurately classified as `NOT_RUN_PLATFORM`. |
| `LIM-06` | Node Runtime | Node 22 Worker Loader Issue | **Node 22 Worker Loader Status on ESM Cablate Google Map:** `node --test Tests/cablate-google-map.integration.mjs` encounters an internal Node 22 module worker loader error (`ERR_INTERNAL_ASSERTION: Unexpected module status 3`). | `cablate-google-map-integration.log`: V8 module loader state machine error during concurrent module resolution. | `cablate-google-map.integration.mjs`. | Upstream Node.js issue in worker thread ESM module loader. Re-run with `--no-addons` or await Node.js patch release. |
