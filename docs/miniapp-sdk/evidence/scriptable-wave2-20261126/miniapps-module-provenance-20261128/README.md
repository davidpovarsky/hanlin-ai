# Failure-only Swift module provenance

The two retained hosted MiniApps builds compiled the current codec source but rejected the caller's decodeNativeList references. The logs do not identify the exact imported module bytes. This change records that missing boundary. It makes no API, cache, compiler-cause, or native acceptance claim.

## Original behavior and time limits

Only the existing fatal mini-build.log path in the paired runner and fatal build.log path in the standalone runner call the collector. Successful builds, other phases, and explicitly allowed paired failures do not call it. Removing each added hook recovers the original runner bytes. Build arguments, original subprocess timeouts, selectors, assertions, source checks, exception types, raw logs, command journals, cleanup, and cache behavior remain unchanged.

Capture receives the original command's existing monotonic start plus its original effective timeout. The paired composite also limits it with the existing original54 job clock, which includes preparation. It starts no collection child after that deadline. The child receives the same absolute deadline and cooperates for at most six seconds; its original Python subprocess supervisor allows at most eight seconds or the remaining original phase time, whichever is smaller. No acceptance deadline is increased. The unchanged workflow job ceiling remains independent. Small local metadata writes and standard process launch/reaping still rely on ordinary filesystem/process operations; this is not a claim that an unresponsive operating system can be forcibly bounded.

The original build error is retained before collection. Collector failures are best effort and cannot make the build pass or replace its original failure. A timed-out original standalone build retains its exact original TimeoutExpired exception.

## Closed observation boundary

The helper walks owned DerivedData and evidence directory descriptors without following symlinks. It considers only named HanlinPlatformContracts module artifacts at the observed producer, flat product, framework-product, and explicit-precompiled-module locations, plus the existing producer/importer Swift file lists and named dependency/output maps. It copies no repository source, credentials, environment dump, arbitrary framework, or whole DerivedData tree.

Each admitted file must be regular, owned by the current runner, single-linked, and unchanged across its read. Symlinks, path traversal, hard links, FIFOs, directories, and concurrently changed files are rejected. Binary artifacts are retained once per SHA-256 under a fresh evidence directory; original relative paths and identities remain separate records. Existing capture directories are never replaced.

Bounds are 8 MiB per file, 16 MiB of retained unique blobs, 32 MiB read, 48 candidates, and 4,096 entries in each of the few named directories. Missing files, rejection, truncation, partial collection, and collector timeout remain explicit. No string or file count is used to decide which module the compiler imported.

Output lives inside the existing acceptance evidence directory at swift-module-provenance/, so the existing artifact upload includes it. controller.json binds the original failed log digest/exit and the actual collection budget. receipt.json binds actual DerivedData identity, paths, file identities, hashes and blobs. The existing prepared-source records and original build log remain authoritative for source and command provenance.
