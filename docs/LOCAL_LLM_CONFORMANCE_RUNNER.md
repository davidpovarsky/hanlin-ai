# Local LLM Conformance Runner Guide (Ollama)

This guide documents how to run the offline/local real-LLM conformance validation lane for Hanlin using Ollama without external API keys.

---

## 1. Prerequisites and Starting Ollama

1. Install Ollama on your host workstation (Windows, macOS, or Linux).
2. Set the environment variable to allow connections across your local network if connecting from an iPad:
   ```powershell
   # Windows PowerShell
   $env:OLLAMA_HOST = "0.0.0.0:11434"
   ollama serve
   ```
   Or on macOS/Linux:
   ```bash
   OLLAMA_HOST=0.0.0.0:11434 ollama serve
   ```
3. Pull the recommended evaluation models:
   ```bash
   # Primary recommended models
   ollama pull qwen3:4b
   ollama pull llama3.2:3b

   # Fallback lightweight models
   ollama pull qwen3:1.7b
   ollama pull llama3.2:1b
   ```

---

## 2. Verifying the OpenAI-Compatible Endpoint

Ollama exposes an OpenAI-compatible endpoint at `/v1/chat/completions`. Verify it responds correctly:

```bash
curl http://127.0.0.1:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer LOCAL_OLLAMA_DUMMY" \
  -d '{
    "model": "llama3.2:3b",
    "messages": [{"role": "user", "content": "ping"}],
    "stream": false
  }'
```

Verify that the response returns HTTP 200 with standard `choices[0].message.content`.

---

## 3. Hanlin Configuration & Dummy Key

Hanlin's remote provider configuration expects a non-empty API key even for unauthenticated local endpoints:
- **API Type**: Select `OpenAI` or `Custom OpenAI Compatible`.
- **Base URL / Endpoint**:
  - If running simulator on the same host: `http://127.0.0.1:11434/v1/chat/completions` (or base `http://127.0.0.1:11434/v1`)
  - If connecting from a physical iPad on LAN: `http://192.168.x.x:11434/v1/chat/completions` (replace `192.168.x.x` with your host's local IPv4 address).
- **API Key**: `LOCAL_OLLAMA_DUMMY` (deterministic dummy key; Ollama ignores authorization headers).
- **Model Name**: e.g., `llama3.2:3b` or `qwen3:4b`.

## 4. Real-LLM Smoke Prompts (L01–L08)

Execute these prompts in sequence to validate the local model's tool calling and multi-round conversation compliance:

### L01: Single Tool Call (Calculator)
- **Prompt**: `"Use the calculator tool to compute 37*19. Do not calculate it yourself."`
- **Expected**: Single tool call `calculator({"expression": "37*19"})` -> tool execution (`703`) -> final response containing 703.

### L02: Skill Activation + Python Execution
- **Prompt**: `"Load the code skill, run local Python to compute sum(i*i for i in range(100)), and use the tool result in your final answer."`
- **Expected**: Round 0 calls `load_skill({"skill": "code"})`. Round 1 calls `python({"code": "..."})`. Round 2 returns final answer `328350`.

### L03: Sequential Tool Dependency
- **Prompt**: `"Use tool A first. Based on its returned value, call tool B. Then answer."`
- **Expected**: Tool A executes in Round 0 -> result fed into Round 1 -> Tool B executes -> final answer in Round 2.

### L04: Error Recovery
- **Prompt**: `"Call the calculator tool with an invalid formula to test error handling, then recover by computing 10+10."`
- **Expected**: Tool returns error -> assistant observes error in history -> re-issues valid tool call or responds with explanation.

### L05: Five-Tool Sequential Chain
- **Prompt**: Chain of 5 sequential tool requests requiring explicit output from each step before continuing.
- **Expected**: 5 consecutive tool calls without losing history or truncating message IDs.

### L06: Multi-Turn Conversation Reference
- **Turn 1**: `"Compute 25*25 with the calculator."`
- **Turn 2**: `"Now take that previous result and add 50 to it using the calculator."`
- **Expected**: Assistant references 625 from prior turn, calls calculator with `625 + 50`, returns 675.

### L07: Hebrew Language Support
- **Prompt**: `"השתמש בכלי החישוב כדי לחשב 47 כפול 23, ורק אחרי קבלת תוצאת הכלי תן תשובה סופית."`
- **Expected**: Model parses Hebrew prompt, generates tool call `47*23`, and emits final answer in Hebrew with `1081`.

### L08: Reasoning Mode + Tool Interaction
- If using reasoning-enabled variants (such as `qwen3:4b` with thinking enabled), prompt the model to reason through a multi-step problem while using tools.
- **Expected**: Reasoning tokens do not corrupt tool call arguments or crash the stream parser.

## 5. Capturing and Analyzing Transcripts

For each smoke scenario, record:
1. `provider request count`: Total roundtrips between client and Ollama.
2. `tool call count`: Number of `tool_calls` generated by the model.
3. `tool IDs`: Exact `id` strings emitted and returned in `role: "tool"` responses.
4. `tool executions`: Execution outcomes from the tool runtime.
5. `final response`: Assistant text output.
6. `rejected continuation`: Whether Ollama rejected any subsequent request due to schema/message ordering mismatch (e.g. HTTP 400).

---

## 6. Distinguishing Model Non-Compliance vs. Hanlin Protocol Failure

When evaluating local models, distinguish between:

| Issue Type | Symptoms | Root Cause |
|---|---|---|
| **Model Non-Compliance** | Model answers in plain text without calling tool; model outputs raw XML/markdown instead of JSON tool call; model hallucinates tool arguments. | Model capability limitation (e.g., smaller 1B/3B models often struggle with strict JSON function calling). |
| **Hanlin Protocol Failure** | HTTP 400 from Ollama on round > 0; missing `tool_call_id` in request; invalid message ordering (`tool` before `assistant`); stream parser stalls on empty delta; crash in `HanlinAISDKAgentEngine`. | Hanlin request serialization or streaming engine bug. |

---

## 7. LAN IP Setup for Physical Device Testing

When running on an iPad connecting to a local host:
1. Find your host IP:
   - Windows: `ipconfig` -> `IPv4 Address: 192.168.x.x`
   - macOS: `ipconfig getifaddr en0`
2. Ensure Windows Defender Firewall or macOS Firewall allows inbound traffic on port `11434`.
3. In Hanlin settings on iPad, configure endpoint as:
   `http://192.168.x.x:11434/v1`
4. Test connectivity from iPad Safari first: open `http://192.168.x.x:11434` — you should see `"Ollama is running"`.
