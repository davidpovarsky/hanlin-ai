## What execution must establish

Each engine uses a separate fresh owned Simulator. The runner must admit an actual historical old app, initially install that app, and execute a newly saved legacy JSON-array action under its original five-parameter metadata. The array contains Hebrew text, the real case UUID, an integer, a fractional number and both Boolean values. The unchanged archive is imported once.

The UI reopens the saved Shortcut and reads its actual name, action, JSON input mode, input, background setting and output chain. The observer requires the original native command, completed handler nonce, canonical typed input, installed package and generation, and private result file. A visible Show Result is required for both runs.

Only after the first genuine result and observed app termination may the setup perform one in-place current-app installation. The second execution must reuse that saved Shortcut and unchanged imported package, with the same data containers and a new real command and handler nonce. No reimport, action recreation or edited input is credited as migration.

The current AI-only xctestrun copy must retain its original environment and exact installation closure while rejecting any implicit MiniApps installation. The current-built descriptor is an execution-time authority; a historical descriptor alone cannot admit it.
