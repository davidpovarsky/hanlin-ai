## Scope

Four additive NativeScript XCTest methods, one each for Text, Integer, Number and
Boolean List. Each creates a real saved Shortcut, appends the original built-in
Get Text from Input → Show Result chain, saves and restarts Shortcuts, reopens and
reads its actual array rows, runs the nonempty list, then removes each row through
the public editor, saves/restarts/reopens and runs the empty list. Eight genuine
action executions are required across four cases. Each pair shares one unchanged
360-second case clock; the original paired 2100-second test command and
210-minute job remain unchanged. The original 38 methods/helpers, 16 Surface
inputs and four JSON cases are preserved.

The public array editor has NOT been observed on the target OS. This is a
fail-closed pilot: it requires one titled public sheet/popover/dialog, actual
Add Item, text-field/switch values, row deletion, and Done controls. Ambiguity or
an unavailable editor retains AX/PNG and fails; there is no JSON, private database,
coordinate or direct-intent substitution. Swift compilation and OS execution
remain NOT_RUN.

Expo's four native-list cases remain a follow-up. No pre-change saved Shortcut
migration, physical-device or broader OS matrix acceptance is claimed.

## Canonical value contract

The exact shipping HanlinValue has distinct integer and number tags. Codable
integer payloads are canonical decimal strings; number payloads are binary64
hex strings. decodeNativeList maps [Int] to integer and [Double] to number.
HanlinRunMiniAppShortcutIntent.makeCommand preserves that input as the actual
canonical invocation parameters.

The observer checks those exact native tags, ordered values and selected native
parameter metadata. JS typeof and plain JSON share one numeric domain; result
readback explicitly does not claim to distinguish Int/Double. Number examples
are exactly representable fractions (-1.25, 0.5, 42.125); integers are -7, 0, 42.
Text includes Hebrew, Han characters and the actual case UUID. Booleans are
true/false. Second runs require [] and distinct real command IDs/nonces.

## Evidence and ownership

The new fixture uses the existing registerWindowFactory/request-handler contract,
receives the real bare array, and writes the exact returned JSON to only that
native window's own state directory. It contains no expected test values, input
type mode or simulated production receipts. No Widget or five-runtime claim.

The reader binds current Git source, actual built/installed standalone app,
XCTest runner/test binaries, actual emitted nine-parameter metadata, original
CLI archive hash, real enabled installed package generation and original retained
archive members. It uses the existing sourceDigest/generation verifier unchanged.
It never calls the old proof_documents (W1 owns the separate Expo correction).

Each run arms against current canonical queue IDs, then requires one fresh
Shortcuts/user-gesture/background command, successful attempt1/no remaining lease,
exact native input, real returned/private per-window result and unique nonce.
Only after XCTest reads that exact JSON from the real built-in chain may the
second step arm. A successful case needs both terminal results and both UI reads.
Pending polling does not repeatedly hash binaries; fresh terminal admission still
rehashes product/source/installation. No production-state writes by the observer.
