# Expo saved native-list acceptance and NativeScript path comparison

Source commit: 7fc9776f8996cd8b3b8838ceaf3fd8f11fddcf29, based on 04e33c45acedd3f372f836b06f17b805bc91293d.

## What changes

Four additional Expo UI cases exercise the shipping Run MiniApp Action with Text List, Integer List, Number List and Boolean List. Each case uses the existing real Shortcuts editor and navigation flow to save, restart, reopen and run a nonempty array through Get Text from Input and Show Result. It then clears the actual array editor, saves/reopens the same Shortcut and runs the empty array. These are four cases with two intended native invocations each; no OS execution is claimed in this source proof.

The new independent Expo package receives the actual handler input, records its observed scalar values/types and actual invocation UUID, writes the exact result to its installed package's State directory, and returns that result only after the real write succeeds. It does not know the expected test values. The observer binds invocation UUID to the original queued command, native canonical element tags, current installed package identity, saved UI values, original receipt/lease checks, exact private-file contents and the actual built-in result chain. Native Int and Double tags are verified in the canonical command separately from JavaScript/JSON's single numeric domain. A public post-completion app-state observation must leave Shortcuts foreground and MiniApps out of the foreground.

The original NativeScript reader retains its window-scoped proof and all original guards. Its one path comparison reuses the already-reviewed lexical duplicate-separator comparison from the Concurrency reader. Raw handler spelling remains in evidence; only equality is normalized. The actual file is still opened at the constructed owned path through the original containment, regular-file and no-symbolic-link checks. This prevents a literal State// filename from rejecting the same owned file. The need is source-bound and corroborated by an actual other NativeScript surface; no failed native Lists execution is invented.

The original affected-validation planner rejected the six existing NativeScript and seven new Expo authoring files as unmapped. Only those thirteen exact paths are added to the existing canonical split owner. Unknown sibling files still fail closed, and the existing two app-unit owners remain the resulting automatic route. The paired OS scope remains an explicit separate manual choice.
