# Original standalone notification OS scope

This candidate wires the existing `testOriginalNotificationAuthorizationAndOSDeliveryToBothEngines` and the unchanged `observe_notification_os_delivery.py` into `run_native_acceptance.py` as the explicit `notification_os` scope. Its default remains `baseline`; the existing baseline7, cross_app23 and production_runtimes25 selections and behaviors are preserved. A mechanical projection recovers the complete original runner AST after removing only the additive notification route.

The new route requires one real XCTest case plus the original worker's five real simulator-push observations: Expo success, duplicate submission and action failure; NativeScript success and duplicate submission. These are three unique native events. An unchanged duplicate receipt does not independently establish a second delegate callback.

## Admission and provenance

The original owned simulator, current build, original embedded entitlements and prepared source identity are prerequisites. The exact source and prepared binary fixture diff remain bound. The actual app, debug dylib, embedded Mach-O files and UI-test binary must match the current built products.

The retained attempt19 proves why prebinding runner/app paths is wrong: XCTest changed both directory identities, while preserving the staged Documents inputs. This candidate waits for the fresh actual UI exchange, then asks CoreSimulator for the current runner, MiniApps and App Group containers. Their MCM identities, actual bundle contents and all three ordinary fixture inputs must match. The route repeats these checks before terminal acceptance. It never invents a directory, seeds a product queue/receipt, grants permission outside the original Apple UI, or recopies inputs after XCTest starts.

The canonical runner identifier is supported by the current generated-info PBX settings and the retained actual built Runner Info and post-XCTest MCM metadata. The current built Info is checked against that identity on every execution. The old directory UUID and MCMMetadataUUID are deliberately treated as different fields.

The unchanged Swift case retains its 600-second allowance, the original worker retains its 650-second deadline, and the standalone native command retains its 1200-second bound. Both child processes have owned process groups. Timeout, stopped children, worker failure, missing observations or changed source/product/container identity cannot become PASS, even if a stopped child later exits zero. A child exiting between poll and signal is reaped without signalling an unrelated process; a cleanup error cannot skip the other child or the controller receipt.

The new scope has not executed on Xcode or a simulator. The root coordinator owns workflow choice publication and dispatch. Acceptance requires the actual selected one-case XCTest result, both zero-exit processes, fresh UI/worker identity, all five raw push records and unchanged corresponding durable product receipts. APNs provider delivery, service-extension invocation, background delivery and physical-device behavior remain separate acceptance requirements.
