# Current Apple Development CSR route

This is an optional signing-probe route, not a change to an app or its user permissions. It remains inactive while `Config/MiniAppsOwnerSigningPlan.json` selects `refresh-profile-readback`.

## Reason for a distinct route

Run 45286408333 stopped in Xcode automatic provisioning. Its retained IDEProvisioningRepair diagnostics found ten member-specific Apple Development certificates and no certificate for the current CI machine, then stopped its certificate-repair step. The account API listed twelve records across current and legacy development types. The existing Apple Distribution identity remains valid and trusted. No existing identity was revoked.

The supported alternative uses exactly one `POST /v1/certificates` with a CSR generated by this task and `certificateType: DEVELOPMENT`. It does not request a legacy iOS Development certificate. Apple will authoritatively accept or reject the current API request; a rejection stops before any archive. A lost response is reconciled by the generated public key without a second POST.

## Identity ownership

The route first checks actual registered iOS development devices and current keychain identity metadata. It reuses an existing valid owner Development identity if available. Otherwise the one new private key stays in a mode-0600 file within this task's mode-0700 runner directory, then is imported into the already owned temporary keychain. Only a newly issued certificate with the exact generated public key, current DEVELOPMENT type, owner team, and a resource ID absent before the task can be used or cleaned up. The temporary certificate is revoked after its archives/exports are complete; existing identities are preserved. If creation or revocation has an uncertain outcome, the exact private key remains in the owned runner context for reconciliation, never in an artifact or log.

Native automatic registration remains `REGISTER_APP_GROUPS=YES`, with the exact Development identity supplied to Xcode. Export uses the already existing Distribution identity and profiles whose actual grants cover the source entitlements. If an automatic archive fails after changing a capability, a fresh App Store profile records the resulting grants immediately.
