## Causes and corrections

| Area | Source finding | Correction |
| --- | --- | --- |
| Missing reasoning | Visibility/composition accepted tool kinds only; header and live-owner logic separately excluded reasoning. | Preserve actual provider reasoning with lifecycle IDs; reuse the existing V17 shared blue sweep on the active leaf or closest visible collapsed ancestor. |
| Empty pre-output activity | Real SDK request admission became hidden transport prose; round creation is not sufficient evidence because inline tools also create rounds. | Explicit model request start/end receipts. Show waiting only while an admitted current request has produced no semantic output. |
| Stale activity | Early pre-dispatch rejection emitted execution start but no matching failure, then suppressed fallback through completedCallIDs. | Emit failure for that original execution before returning the rejection. No dispatch or replay is introduced. |
| Technical Live Activity subtitle | The title was derived from ByteCountFormatter. | Use actual waiting, reasoning, answer, tool, approval and terminal state. Keep counts internal. |
| Native approval not reflected | Native Host consent bypassed the tool adapter callback. | Capture the admitted operation at session entry and retain that original operation for the pending consent request ID. Resolve before forwarding the UI update. |
| Missed Live Activity transition | Observer compared against a later snapshot that had never been published. | Initialize comparisons from the exact snapshot published at launch. |
| Broken glass connection | Minimum input rose from 52 to 102 points while the plus remained bottom-aligned: panel-to-plus gap became 63, beyond the original 32-point merge distance. | Extend only the existing panel material by inputHeight minus 52, preserving content layout, original three surfaces, spacing, IDs and the plus position. |

| Blank rich-block icons | Rich renderer depended on late conditional global attachment registration. | Resolve the in-memory rich-block attachment through its own public native view-provider override. Native before/after comparison is required to confirm the displayed regression. |
