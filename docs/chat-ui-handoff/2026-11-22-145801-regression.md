## Rich attachment correction after native run 45034845488

Renderer commit `eebcae3b085d6ab65541794e2f055f528a071856` explicitly
sets the rich attachment's file type after its nil-content initializer. It also
separates immutable canonical value equality from mounted attachment identity.
Previously, a mounted copy compared equal to an unowned canonical attachment or
another text view's mounted copy. Attributed-string caching/uniquing could retain
that other value, losing the owner which supplies the rendering environment.
The provider's no-environment path clears its hosted content and produces the
fallback height seen in native6. The immutable ownership tag and object-identity
hash for mounted copies avoid that replacement without depending on weak-owner
lifetime. Canonical streaming-tail comparisons remain content-based.

The existing provider test now checks stored ownership across two independent
text views and verifies canonical isolation. The existing three renderer methods,
geometry thresholds and selection assertions remain intact. The fixture works
against the old renderer's APIs, and its original provider unwrap is still at
line 34. Its updated exact SHA-256 is
`dff43fa678467ad4398226b31faf7001cfae5e111515a838dfe4fd4bd8369788`;
the baseline recognizer is rebound to that fixture without widening the accepted
failure, counts, exit status or finalization requirements. Light, opaque fixture
captures and concrete bounds/subview counts improve diagnosis.

Swift syntax parsing and whitespace validation passed for the two renderer
files. A Windows interpreter probe could not load Foundation JIT symbols and
provides no behavioral result. Native acceptance of this correction is still
pending. The failed native6 evidence is retained unchanged. Composer/activity
production source and the selected frozen Runtime are unchanged.
